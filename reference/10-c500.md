# MetaX C500 (xcore1000)

The rest of this skill was written against the C550 (MXC550). This page records what is
known about profiling on the **C500**. Facts below come from a C500 host with MACA SDK
3.7.0.38 and are marked by how they were checked. Do not carry C550 numbers, thresholds,
counter names or peaks over to the C500. A fact not listed here is unchecked on the C500.

---

## Device facts (from the runtime on a C500)

Read with `mcDeviceGetAttribute` on MACA 3.7.0.38 (2026-10-17):

| Fact | C500 value |
|---|---|
| Device name | `MetaX C500` |
| Total memory | 68283269120 bytes (~63.6 GiB) |
| Warp size | 64 |
| Multiprocessors | 104 |
| Max threads per block | 1024 |
| Max threads per multiprocessor | 2048 |
| Shared memory per block / per multiprocessor | 65536 / 65536 bytes |
| Registers per multiprocessor | 131072 |
| L2 cache | 8388608 bytes |
| Max grid dimension (x, y, z) | 2147483647 each |

Warp size is **64**, not 32. Block-size sweeps and "threads per warp" reasoning must use
that, and warp-level CUDA intrinsics written for 32 lanes do not port unchanged.

## Tool locations (MACA 3.7.0.38 on a C500)

| Tool | Path | Status on the checked host |
|---|---|---|
| `mcTracer` | `/opt/maca-3.7.0/bin/mcTracer` | present; version `3.7.0.38` |
| `mxcc` | `/opt/maca-3.7.0/mxgpu_llvm/bin/mxcc` | present; **not** under `bin/` |
| `mcProfiler` CLI | — | **no executable** on the checked host (not on PATH, none under `/opt` or `/usr`) |
| Profiler API | `mcProfilerStart` / `mcProfilerStop` in the runtime; counter config sample `/opt/maca-3.7.0/samples/0_Introduction/profilerScope/mcProfiler.json` | present; sample README sets `MCTX_TARGET_PROFILE_PATH` |
| Activity library | `/opt/maca-3.7.0/lib/libmcpti.so` | present (used by MCPTI kernel timing) |
| Runtime header | `/opt/maca-3.7.0/include/mcr/mc_runtime.h` | `mc*` API (`mcMalloc`, `mcMemcpy`, `mcDeviceSynchronize`) |

`mcTracer --help` on 3.7.0.38 lists exactly `--help`, `--debug`, `--mctx`, `--odname`,
`--name` (default prefix `tracer_out`) and `--attach <pid>` (stop with `ctrl+t`).

Because there is no `mcProfiler` executable, **`mcProfiler --csv` (Recipe 2) cannot run on
that C500 host**, and the `dram_pct` / `sm_pct` columns it would provide are unavailable.
The in-process API route (Recipe 3, `profilerScope` with `MCTX_TARGET_PROFILE_PATH`) is
present but was not exercised on the C500; its counter names in the sample
(`RM_PERF_BUSY_CYCLES_P0`, …) are not mapped to canonical metrics. Until one is checked,
treat a C500 profile as a mcTracer timeline plus source/launch analysis, report
`profiler_available: false`, and mark bandwidth or compute conclusions
`confidence: inferred` (playbook pattern H).

## Building a harness on the C500

The harness template compiles on the C500 with either:

```bash
M=/opt/maca-3.7.0
$M/mxgpu_llvm/bin/mxcc -x maca -offload-arch native -gcc-version=11 kernel.cpp -o kernel_harness
$M/mxgpu_llvm/bin/mxcc -x maca --offload-arch=xcore1000 -gcc-version=11 kernel.cpp -o kernel_harness
```

Without `-gcc-version=11`, the runtime headers fail with `'tuple' file not found`.
Checked by compiling the template, not by running it.

## Device access

- Do not profile on a card another process holds. Check with `mx-smi` first; on a shared
  host take the card through the host's allocator or broker, not by picking an index.
- `/dev/mxcd` access needs the `video` group or a container started with
  `--device=/dev/mxcd --group-add video` (`09-common-issues.md`).

---

## Timer resolution caveat

Device timing through MCPTI on xcore1000 occasionally records a dispatch with
`start_ns == end_ns`. In one 61-task run this was 9 of 473000 timed dispatches,
for kernels whose other samples were 2.8–11.8 us. Treat such a record as a defective
timer record, not a 0 ms kernel: drop the whole cohort and re-measure, rather than
averaging a zero in. mcTracer timelines were not checked for the same effect.
